## 이해가 어려웠던 내용
> 설명이 어렵거나 개념이 잘 이해되지 않았던 부분
- 49p. 대규모 데이터를 다루는 프로그램 작성법 세번째 팁. 검색 엔진을 만들어서 속도를 확보한다?
- `top` -> load average : 1분, 5분, 15분 동안에 단위 시간당 대기된 태스크의 수.
  - load average 에 이상이 있다면 이어서 cpu 사용량 , I/O 대기율을 보라. `sar` 명령어. 

| load / 코어수 | 해석 |
|---|---|
| ~0.7 이하 | 정상 |
| 0.7 ~ 1.0 | 여유 없음, 관찰 필요 |
| 1.0 초과 | 대기 큐 발생, 처리 지연 시작 |
| 2.0 이상 | 확실한 이상, 즉시 원인 파악 |

세 개의 숫자는 추세로 읽습니다
`0.5, 2.0, 5.0` (1분/5분/15분) 처럼 뒤로 갈수록 크면 과부하가 해소되는 중이고, `5.0, 2.0, 0.5` 면 지금 막 문제가 터지는 중입니다. 1분 값만 잠깐 튄 건 대부분 무시해도 됩니다.
