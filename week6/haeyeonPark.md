## 핵심 내용 요약
- 웹서비스의 핵심
    - 1. 저비용 고효율, 2. 확장성 3. 개발속도(ci/cd, 인프라 확장성, 빠른 롤백)
- 부하를 측정하기 위한 항목
    - load average: cpu가 할당되지 않아서 대기상태에 있는 프로세스 수의 평균치. -> (코어수 절반~코어수 이하 권장)
    - 메모리, cpu
- 용도에 맞는 튜닝-> 사용자/봇서버를 나누었다면, 전자는 응답시간 후자는 효율을 중시하는 설정 선택 가능
- 다중화? 서버가 1/2대 정지해도 처리가능하도록 확보해두는것.
    - fail over(장애 극복), failback(정상 복귀) 
    - AP 서버 -> LB 동작.
    - DB 서버 -> 멀티 슬레이브 / 멀티 마스터
- 시스템 안정성과 자원효율에는 trade off가 있다.
- 시스템 불안정 요인
    - 1. 기능 추가 2. 메모리 누수 3. 지뢰 4. 사용자 액세스 패턴 5. 데이터량 증가 6. 외부 dependency 추가 7. 하드웨어 장애(메모리, hdd, 네트워크)
