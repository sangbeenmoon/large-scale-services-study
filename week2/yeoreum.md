## 핵심 내용 요약
데이터 접근 성능을 높이기 위해서 캐시를 최대한 활용해서 디스크 I/O를 줄이는 게 중요하다.
- 데이터 규모가 커질수록 단순한 서버 증설보다 **접근 패턴과 국소성을 고려한 데이터 분산**이 필요하다.
- DB에서는 **메모리 활용, 적절한 인덱스, 데이터 크기 관리**가 성능에 큰 영향을 준다.
- OS 재시작이나 성능 테스트 시에는 **캐시가 비어 있는 상태와 충분히 올라온 상태의 차이**를 고려해야 한다.
- 확장이 필요할 때는 단순 복제보다 Replica, Partitioning, Sharding 등 **목적에 맞는 분산 전략**을 선택해야 한다.

## 인상 깊은 내용
- DB 서버에서 I/O 병목이 생겼을 때 서버만 단순히 늘리면, 각 서버의 캐시가 부족한 문제는 그대로 남을 수 있다.
- **각 서버가 담당하는 데이터 범위를 줄여 자주 사용하는 데이터가 메모리에 충분히 올라갈 수 있도록 하는 것이 중요하다.**
