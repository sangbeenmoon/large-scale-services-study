## 핵심 내용 요약
#### OS 캐시 구조
- Linux 는 페이지 단위로 디스크 내 데이터를 캐시하고, 캐시된 데이터는 evict 되지 않는 한 해제되지 않고 남아 있는다.
- 메모리 상향 (scale up) -> 페이지 캐시 용량 증가 -> 디스크 접근 횟수 감소

#### I/O 부하를 줄이는 방법
- 1. 메모리 상향 (scale up)
- 2. 서버 대수 증설 (scale out)
  - 이때, 단순히 서버 대수만 늘린다고 I/O 부하가 감소하는 것은 아님.

#### locality 를 살리는 분산
- 액세스 패턴을 고려한 분산 -> 각 서버마다 캐시하고 있는 내용이 다름. -> 캐시 가능한 메모리 공간이 커진다.
  - e.g. DB 테이블 파티셔닝. ID 단위 파티셔닝.
    - 문제점 : cardinality 가 변경되었을 때 리밸런싱이 필요할 수 있음.
- 페이지 캐시를 고려한 서버 운영
  - OS 가동 직후 warm up 필요. (DB 에서 자주 사용되는 데이터를 한번 조회한다.)
  - 성능/부하 테스트할 때는 초깃값을 버리자.ƒ

#### 인덱스를 올바르게 운용하기
- Mysql 의 인덱스는 기본적으로 B+ tree 데이터 구조를 사용한다.
