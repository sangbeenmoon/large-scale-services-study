## 핵심 내용 요약
- 페이지 캐시 = OS가 디스크에서 읽은 데이터를 메모리에 남겨두는것.
    - 페이지 = 디스크를 캐싱하는 단위, 4KB
- I/O 부하 줄이는법
    - 데이터 < 물리 메모리의 경우, 메모리를 늘리면 페이지캐시를 통해 해결할수 있다.
    - 압축해서 데이터 사이즈를 줄일수 있다.
    - 메모리 비용과 최적화 공수 사이의 trade off를 고려하자.
- 전부 캐싱할수 없다면 -> 국소성을 고려하여 여러대의 서버로 확장
    - 테이블단위 분할: 함께 액세스 하는 경우가 많은 경우 같은 서버에 위치 고려
    - 테이블 데이터 분할: e.g. ID의 첫문자로 어디 저장할지 결정하여 분산해서 저장
    - 액세스 패턴에 따라 AP/DB를 아예 분리
- 인덱스 -> mySQL의 경우 b tree를 사용한다.
- 인덱스 최적화 -> explain을 통해 의도에 맞는 인덱스가 사용되는지 미리 점검가능하다
